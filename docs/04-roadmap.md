# 로드맵

> **2026-05-31 미션 개정.** 목표가 "Binance 현물 1분봉 단타"에서
> **"더 긴 타임프레임(스윙) 기반 실제 수익"**으로 전환됨. 아래 두 가지가
> 설계 전체를 다시 규정한다:
>
> 1. **성공의 정의 = BTC Buy & Hold를 위험조정 기준으로 이기는 것.**
>    현금 대비 +가 아니다. 같은 기간 BTC를 그냥 들고 있는 것보다
>    위험조정(Sharpe·MDD) 우위가 없으면 실패다. 크립토 B&H는 잔혹한 벤치마크다.
> 2. **수수료 마찰 회피.** 1분봉 단타는 왕복 0.2% 수수료가 엣지를 통째로
>    잡아먹는다. 4h~1d 스윙은 연 거래 수십 회 → 마찰 감당 가능 + 추세 포착.
>    크립토에서 OOS로 살아남는 거의 유일한 아노말리가 추세추종이다.

## 구축 완료 인프라 (단타 기준으로 지어졌으나 재사용 가능)

타임프레임에 독립적이라 코드는 그대로 쓴다. **단, 이 인프라로 뽑은 기존
검증 결과는 전부 무효다** — 1분봉 1달치 기준이었고, 새 무대(스윙·다년치)에서
처음부터 다시 검증해야 한다.

- **[기존 Stage 1] 오프라인 백테스트** — 벡터화 엔진(next-bar open, 수수료), Binance REST 다운로더 → Parquet, EMA 베이스라인, 합성 데이터 스모크 테스트
- **[기존 Stage 2] 전략 다양화** — EMA 크로스 / 변동성 돌파 / RSI 평균회귀 / 볼린저+ATR, 레지스트리, `mm compare`, 시각화(`--plot-dir`)
- **[기존 Stage 3] 견고성 검증 도구** — `mm walkforward` / `mm grid` / `mm mc` / `mm feesweep`
- **[기존 Stage 4] 실시간 인프라** — kline WebSocket(재연결), SignalEngine, 주문 상태머신, PaperExecutor, SimulatedRouter / BinanceTestnetRouter, `mm live`
- **[기존 Stage 5] 리스크 매니저** — 포지션 사이저(고정/ATR), 일일 손실 컷, 킬 스위치(`mm kill`), 슬리피지 측정

## 현재 위치: **재출발** — 새 무대에서 처음부터 검증

목표가 바뀐 순간, 우리는 "Stage 6 실거래 직전"이 아니라 사실상
**"아직 B&H를 이기는 전략을 하나도 증명 못 한 출발점"**에 서 있다.
이건 후퇴가 아니라 정직한 재출발이다.

### Stage 1 — 벤치마크 + 데이터 기반 ⬜

자기기만 방지의 마지막 빠진 조각을 먼저 박는다.

- [ ] **Buy & Hold 벤치마크를 1급 시민으로** — `BacktestResult`에
      `bh_return` / `bh_sharpe` / `bh_max_drawdown`, 그리고 전략의 **초과수익**
      (alpha) 필드 추가
- [ ] **모든 리포트에 전략 vs B&H 나란히** — `mm backtest` / `mm compare` /
      `mm walkforward` 출력에 벤치마크 열. B&H 못 이기면 시각적으로 즉시 드러나게
- [ ] **타임프레임 전환** — `default_interval` `1m` → `4h` (스윙 기본)
- [ ] **다년치 데이터셋 확보** — BTC 2~3년치 4h/1d 다운로드. 1d봉 1달 = 30봉
      = 통계적 무의미. 강세장·약세장·횡보장을 모두 거친 데이터 필요
- [ ] (선택) 데이터 갭/무결성 체크 — 다년치는 누락 봉 가능성 ↑

### Stage 2 — 스윙 전략 탐색 ⬜

추세추종으로 무게를 옮긴다. 기존 전략은 재튜닝이 아니라 **재평가** 대상.

- [ ] **추세추종 강화** — 돈치안 채널 브레이크아웃, 추세 레짐 필터
      (예: 200봉 MA 위에서만 롱), 모멘텀
- [ ] **기존 4종 재평가** — 4h/1d에서 어떻게 보이는지. 평균회귀는 추세장에서
      불리하므로 비교용으로만 유지
- [ ] **전 전략 vs B&H 비교** — B&H 위험조정 못 이기는 전략은 솔직히 "탈락" 표기

### Stage 3 — 견고성 재실행 (스윙 캘리브레이션) ⬜

거래가 드물수록 과적합 위험이 폭증한다. 역설적으로 **긴 타임프레임일수록
이 단계가 더 중요**하다.

- [ ] **walk-forward 윈도우 재계산** — `train_bars`/`test_bars`가 이제 "일" 단위.
      4h봉 기준 합리적 train/test 길이 재설정
- [ ] **게이트 재정의** — 기존 "OOS Sharpe > 1.0" →
      **"OOS에서 B&H 대비 위험조정 초과 + Monte Carlo p < 0.05 + fee sweep robust"**
- [ ] **통과 전략이 0개일 수 있음을 받아들인다** — 그것도 정당한 결론.
      억지로 라이브 가는 것이 이 프로젝트가 막으려는 바로 그 자기기만이다

### Stage 4 — 페이퍼 트레이딩 (게이트 통과 전략만) ⬜

- [ ] Stage 3 게이트를 통과한 전략만 Testnet 페이퍼로
- [ ] **스윙 특유의 함정**: 거래가 드물어 "4주 페이퍼"로는 거래 수 부족 →
      관찰 기간 연장 또는 다심볼로 거래 수 확보 고려
- [ ] 페이퍼 PnL vs 백테스트 정합성 측정

### Stage 5 — 실거래 (소액) ⬜

조건:
- Stage 3 게이트 통과 (OOS에서 B&H 위험조정 초과)
- Stage 4 페이퍼에서 백테스트와 정합 (편차 < 30%)
- 리스크 장치 전부 활성

- [ ] 실제 API 키, **소액부터** (`max_position_usdt` 소액)
- [ ] Telegram/Discord 알림, 일일 PnL 리포트
- [ ] 매주 페이퍼 vs 라이브 PnL 비교

### Stage 6 — 운영 ⬜

- [ ] VPS 배포, systemd/Docker 자동 재시작, 로그 영구 보관
- [ ] 대시보드, 정기 재검증 (성과 저하 자동 탐지)

## 안 할 것 (적어도 당분간)

- HFT / 마켓메이킹 — 스윙으로 전환하며 더더욱 무관
- 옵션 — 복잡도 과다
- 대체 거래소 — Binance 마스터 후
- ML 가격 예측 — 피처 인프라부터

> **선물/숏은 보류.** 하락장 기회를 포기하는 대가가 있지만, 현물 롱온리는
> 청산·펀딩·레버리지 리스크 로직이 없어 단순하다. 스윙 + B&H 초과를 먼저
> 증명한 뒤 재검토.
